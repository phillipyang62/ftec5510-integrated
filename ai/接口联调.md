# AI 子模块接口联调

## 三块分工

- **前端**直接获取和展示行情等信息，也负责展示 AI 返回的结果。
- **中台**从上游抓取币种及市场报价，并提供用户持仓和挂单的查询。
- **AI**使用问卷打分、币价和中台数据，提供投教、模拟投资建议和持仓风险摘要。

## AI 需要的数据

- **币价**：币种、币价、用什么币计价、报价来源。用前端已取到的行情或中台抓取的行情，联调时按现有数据入口对接。
- **中台数据**：持仓给币种和数量，挂单给买卖方向和数量。
- **问卷数据**：对应用户的问卷打分。

前端和中台先提供现有数据样例。接口地址、字段名和格式按实际情况对接。

## 通用约定

AI 服务默认地址为 `http://127.0.0.1:8000`。同机可直接访问。跨机器联调时，用 `--host` 指定 AI 机器的内网 IPv4，并设置 `AI_MVP_API_TOKEN`。其他组通过该内网地址和启动端口访问。

除 `GET /health` 外，配置服务凭证后，AI 接口均要求 `Authorization: Bearer <AI_MVP_API_TOKEN>`。向 AI 提交 JSON 时使用 `Content-Type: application/json`，请求体上限为 256 KiB。普通 HTTP 客户端会自动设置 `Content-Length`。

`user_id` 为 1–64 个 ASCII 字母、数字、下划线或连字符，例如 `student_001`。业务后端根据登录会话确定该 ID，并与问卷端和中台使用同一映射。服务凭证保存在后端。当前服务的浏览器接入采用业务后端或同源代理，跨域预检需要由接入层处理。

行情和账户 `as_of` 使用带时区的 RFC 3339 时间，精度为秒或最多六位小数，例如 `2026-11-18T08:00:00Z` 或 `2026-11-18T16:00:00+08:00`。AI 规范化为 UTC。价格和数量推荐用十进制字符串传递，避免浮点精度损失。代码接受有限 JSON 数字，拒绝布尔值、NaN 和 Infinity。金额字段的原始十进制表示最多 80 字符。

## AI 当前接收的问卷测评

请求为 `PUT /v1/profiles/student_001`，带 AI 服务凭证。一次提交替换该用户的当前画像，成功后返回 HTTP 200。读取当前画像使用 `GET /v1/profiles/student_001`，用户尚无画像时返回 HTTP 404。

必填内容如下。

- `assessment` 为对象。其中 `dimensions.FC`、`RA`、`KE`、`BD`、`OC` 为五项归一化分数，均为 0–100 的有限 JSON 数字，可以为零。
- `assessment.rai` 为问卷端已计算的 0–100 整数。AI 校验财务承受力封顶，接受上限为 `floor(FC + 20.5)`，以容纳最终整数四舍五入。
- `assessment.risk_level` 与 RAI 分段一致。C1 对应 0–24，C2 对应 25–44，C3 对应 45–64，C4 对应 65–79，C5 对应 80–100。
- `assessment.product_cap` 为 R1–R5，序号必须与 C 档一致。

可选内容如下。

- 外层 `questionnaire_version` 默认为 `1.0.0`，`source` 默认为 `questionnaire`。两者为最多 64 字符的代码，首字符为 ASCII 字母或数字，后续可含字母、数字、下划线、点、冒号和连字符。
- `assessment.allocation_range` 可省略或为 `null`。提供时为 `{min_pct, max_pct}`，两项均为 0–100 的有限数字，且前者小于或等于后者。
- `assessment.flags` 和 `assessment.prohibitions` 可省略，默认 `[]`。每组最多 16 个代码，每个代码遵守上述 64 字符规则。联调时需约定代码字典。目前任一禁止项都会暂停全部模拟建议。
- 外层 `dimensions.wealth_band` 可省略或为 `null`，提供时为 `low`、`medium` 或 `high`，来自独立财富分档。

请求示例。

```json
{
  "questionnaire_version": "1.0.0",
  "source": "questionnaire",
  "dimensions": {"wealth_band": "medium"},
  "assessment": {
    "dimensions": {"FC": 62, "RA": 65, "KE": 75, "BD": 60, "OC": 55},
    "rai": 63,
    "risk_level": "C3",
    "product_cap": "R3",
    "allocation_range": {"min_pct": 5, "max_pct": 15},
    "flags": ["short_horizon"],
    "prohibitions": []
  }
}
```

HTTP 200 响应示例，`updated_at` 由 AI 服务器生成。

```json
{
  "user_id": "student_001",
  "risk_willingness": null,
  "risk_capacity": null,
  "wealth_band": "medium",
  "knowledge_level": null,
  "risk_ceiling": "C3",
  "route": "advisory",
  "reasons": ["assessment_risk_level_verified", "ke_allows_advisory"],
  "missing_fields": [],
  "questionnaire_version": "1.0.0",
  "source": "questionnaire",
  "updated_at": "2026-11-18T08:00:00.000000+00:00",
  "assessment": {
    "dimensions": {"FC": 62, "RA": 65, "KE": 75, "BD": 60, "OC": 55},
    "rai": 63,
    "risk_level": "C3",
    "product_cap": "R3",
    "allocation_range": {"min_pct": 5, "max_pct": 15},
    "flags": ["short_horizon"],
    "prohibitions": []
  }
}
```

当前分流约定为 `KE < 45` 进入 `education`，其余进入 `advisory`。知识阈值、百分比区间的字段名和标记代码属于本次接口约定。配置区间目前随画像传递，模拟场景按知识路线、产品上限与禁止项筛选。AI 只保存约定的派生字段。原始题目、逐题答案和自由文本字段不会进入画像存储或画像模型上下文。

兼容的旧版 `dimensions` 档位接口仍可使用。首次五维联调请采用上述 `assessment` 结构，缺项或 C/R 档位不一致会返回 HTTP 400。

## 读取前端或中台的币价

`AI_MVP_MARKET_URL` 指向提供币价的前端或中台服务。例如配置 `http://middle-office:8200/api` 后，当前适配器会调用 `GET /api/quotes`。如果使用不同的路径或字段，按实际样例适配。上游凭证可通过 `AI_MVP_MARKET_TOKEN` 传入，AI 使用 Bearer 鉴权。默认超时 2 秒，响应体上限 256 KiB。

查询参数 `q` 为交易对、资产代码、名称或别名。`limit` 为希望返回的条数，当前 AI 上游请求范围为 2–20。即使前端只需要一条结果，AI 也至少请求两个候选，以检测歧义。

请求示例。

```http
GET /api/quotes?q=BTC%2FUSDT&limit=5 HTTP/1.1
Accept: application/json
Authorization: Bearer <AI_MVP_MARKET_TOKEN>
```

行情服务 HTTP 200 响应示例。

```json
{
  "quotes": [
    {
      "symbol": "BTC/USDT",
      "price": "68000.50",
      "as_of": "2026-11-18T08:00:00Z",
      "source": "example_exchange",
      "name": "Bitcoin",
      "aliases": ["比特币", "大饼"]
    }
  ]
}
```

每条报价必填 `symbol`、`price`、`as_of`、`source`。`price` 必须大于零，`source` 为非空字符串。`symbol` 推荐统一为 `BASE/QUOTE`，两侧为 1–20 个 ASCII 字母或数字，也支持 `BTC-USDT`、`BTC_USDT`。紧凑代码 `BTCUSDT` 需要同时提供 `base: "BTC"` 和 `quote: "USDT"`，并保持一致。

`name` 为可选非空字符串或 `null`，`aliases` 为可选数组，元素为非空字符串。主动查询会在返回候选中重新做名称匹配，因此查询中文名时，需要在 `name` 或 `aliases` 中返回该名称。未知查询返回 HTTP 200 和 `{"quotes": []}`。

查询 `BTC` 或“比特币”命中 BTC/USDT 与 BTC/USD 时，上游至少返回两个不同交易对，保留对应名称或别名。AI 将返回 `ambiguous` 供用户选择。上游每次最多返回 50 条候选，AI 的 `match_count` 表示本次返回候选内的命中数。首次演示优先用完整交易对确保双方币种一致。

AI 拒收超过服务时钟 15 秒的未来报价。默认将超过 120 秒的报价标为 `stale`，`AI_MVP_QUOTE_MAX_AGE_SECONDS` 可调整阈值。真实请求保留行情采集时刻。HTTP 错误、超时或无效响应时，AI 尝试已有推送缓存，并返回 `upstream_status: "unavailable"`。成功的主动查询为空时，直接表示本次无匹配报价。

## 行情推送与 AI 对外查询

前端或中台也可将已有行情推送给 AI。当前接口为 `POST /v1/market/quotes`，请求体为上述 `{ "quotes": [...] }`，要求 1–500 条。向 AI 推送使用 AI 服务凭证。首次推送可包含 `name` 和 `aliases`，后续价格更新可省略这两项以保留原检索信息，显式 `name: null` 或 `aliases: []` 会清空它们。

HTTP 200 响应示例。

```json
{"accepted": 1, "ignored": 0}
```

`accepted` 统计实际改变的交易对数量。同批多条相同交易对会合并，旧时间或完全相同的数据可以重试且不增加该数。整批校验失败时，该批不会写入。缓存保存在当前 AI 进程中，重启后需要重新推送。配置主动行情源后优先查上游，遇到上游故障再尝试此缓存。

前端查询 AI 使用 `GET /v1/market/quotes?q=BTC%2FUSDT&limit=5`，其中 `q` 为 1–80 字符，`limit` 为 1–20，默认 5。假设查询发生在示例报价之后两秒，HTTP 200 响应如下。

```json
{
  "query": "BTC/USDT",
  "status": "exact",
  "match_count": 1,
  "matches": [
    {
      "symbol": "BTC/USDT",
      "base": "BTC",
      "quote": "USDT",
      "price": "68000.50",
      "as_of": "2026-11-18T08:00:00.000000Z",
      "source": "example_exchange",
      "name": "Bitcoin",
      "aliases": ["比特币", "大饼"],
      "freshness": "fresh",
      "age_seconds": 2.0
    }
  ],
  "lookup_source": "market_provider",
  "upstream_status": "ok"
}
```

AI 查询 `status` 可为 `exact`、`ambiguous`、`match`、`not_found`。上游故障且缓存无结果时为 `unavailable`。`freshness` 为 `fresh`、`stale` 或 `future`。仅唯一精确命中且新鲜的报价进入模型上下文。未配置主动行情源时从推送缓存读取，响应省略 `lookup_source` 和 `upstream_status`。

## 中台账户快照

AI 配置 `AI_MVP_TRADING_URL` 为中台服务前缀，如 `http://middle-office:8200/api`。当前适配器调用 `GET /api/accounts/{user_id}/snapshot`。可选凭证配置为 `AI_MVP_TRADING_TOKEN`，AI 请求携带该值对应的 Bearer 凭证。接入中台时，AI 服务本身还必须设置 `AI_MVP_API_TOKEN`。

请求示例。

```http
GET /api/accounts/student_001/snapshot HTTP/1.1
Accept: application/json
Authorization: Bearer <AI_MVP_TRADING_TOKEN>
```

中台 HTTP 200 响应示例。

```json
{
  "as_of": "2026-11-18T08:00:00Z",
  "positions": [
    {"symbol": "BTC", "quantity": "0.10"},
    {"symbol": "USDT", "quantity": "1000"}
  ],
  "open_orders": [
    {"symbol": "ETH/USDT", "side": "buy", "quantity": "0.20", "limit_price": "3000.00", "status": "open"}
  ],
  "truncated": false
}
```

必填 `as_of`、`positions` 数组和 `open_orders` 数组。两个数组均允许为空，已确认的空账户返回 HTTP 200 和以下结构。

```json
{"as_of": "2026-11-18T08:00:00Z", "positions": [], "open_orders": [], "truncated": false}
```

持仓行必填 `symbol` 和 `quantity`。`symbol` 可以是资产代码或标准交易对，`quantity` 为基础资产数量，支持正数、零和负数。挂单行必填 `symbol`、`side` 和 `quantity`，`side` 为 `buy` 或 `sell`，挂单数量大于零。可选 `limit_price` 大于零，省略或 `null` 用于没有限价的订单。可选 `status` 为短 ASCII 状态代码，例如 `open`、`partially_filled`，规范化后匹配 `[a-z][a-z0-9_]{0,31}`。

`truncated` 为可选布尔值，默认 `false`。中台已截断或只返回部分数据时填写 `true`。AI 还会将每个数组截至前 50 条，并保留截断标记。上游返回全部状态正常的快照时，AI 输出增加 `state: "ok"`，仅保留约定字段。

上游未知账户、未授权或不可用可返回对应的 HTTP 404、401/403、503。适配器将这些非成功状态和超时统一转成 `{"state":"unavailable","reason":"upstream_unavailable"}`，不解析上游错误体。字段缺失、无效时间、超大响应等会转成 `reason: "invalid_response"`。空账户仅在成功返回空数组时成立。

默认请求超时为 2 秒，响应体上限 256 KiB，当前适配器不跟随重定向。AI 尚未配置中台时，账户结果为 `{"state":"not_configured"}`。中台账户数据通过本地模型或模板解释。前端将账户卡片与普通聊天历史分别保管，提交历史前只保留本次需要的文本。

## 前端调用对话和持仓风险

对话请求为 `POST /v1/chat`，带 AI 服务凭证。

```json
{
  "user_id": "student_001",
  "message": "比特币现在多少钱？看看我的持仓。",
  "market_queries": ["BTC/USDT"],
  "include_account": true,
  "include_simulation": false,
  "history": []
}
```

必填 `user_id` 和 1–2000 字符的 `message`。`market_queries` 可省略，最多 5 个查询，每个 1–80 字符。主动行情联调建议显式传查询词或完整交易对。`include_account`、`include_simulation` 为可选布尔值，默认 `false`。`history` 默认空数组，最多 6 条，每条包含 `role: "user"` 或 `"assistant"` 以及 1–800 字符的 `content`。

响应包含 `reply`、`generation`、`mode`、`risk_ceiling`、`profile_reasons`、`profile_updated_at`、`trace_id`、`market_requested`、`market`、`account`。五维画像增加 `product_cap`，请求模拟方案时增加 `simulation`。`market` 中每项采用上文 AI 行情查询结构，`account` 为规范化账户快照、状态对象或 `null`。前端以这些结构化字段展示数据事实。

`mode` 为 `clarify`、`education` 或 `advisory`。五维画像下 `risk_ceiling` 为 C1–C5，旧画像可能为 `low`、`medium` 或 `high`，未完成画像时为 `null`。明确请求模拟方案使用 `include_simulation: true`。结构化 `simulation.scenarios` 带场景风险档与依据字段，用于展示后端筛选出的课堂假设情景。

持仓风险请求为 `GET /v1/risk/student_001?quote_currency=USDT`，`quote_currency` 默认 `USDT`，允许 1–20 个 ASCII 字母或数字。AI 读取账户快照并按需查价，结果 `state` 为 `ok`、`partial`、`unavailable` 或 `not_configured`。

返回的 `positions` 逐项包含估值状态、数量、估值金额与报价时间依据，金额为指定计价币的十进制字符串。`summary` 包含已覆盖部分的净值、总敞口、多头和空头敞口。`summary.complete: true` 时，`net_value`、`gross_exposure` 和 `largest_asset.gross_concentration_pct` 才可作为完整快照指标。`partial` 时这些全量字段为 `null`，按 `reasons` 提示缺价、过期、不同计价币、截断或查询上限等原因。

当前风险计算最多处理前 50 条持仓、查询 10 个不同的非现金交易对，账户和报价默认使用同一 120 秒新鲜度阈值。同名计价资产按单位值估值，其他资产要求指定计价币的精确报价。挂单仅计数。这些指标描述本次快照内支持的持仓估值与敞口。

## 本地演示与实际接入

`python -m ai_mvp` 启动本地服务。另一个终端运行 `python -X utf8 -m ai_mvp.demo`，会写入两位虚构用户和两条 `source: "demo"` 的模拟报价。运行此脚本前清除主动行情配置，可使演示始终使用脚本推送的模拟数据。

使用当前适配器时分别设置 `AI_MVP_MARKET_URL` 与 `AI_MVP_TRADING_URL`，按需设置对应 Token。AI 的问卷接口接收派生测评。`GET /health` 可检查 `market_configured`、`trading_configured`、`model_configured`、`remote_model_configured`。这些字段表示通道已配置，实际连通性通过对应业务查询确认。

对话生成使用显式配置的模型 API。`generation` 显示生成方式，`model_status` 给出模型调用与授权状态。DeepSeek Key 和启动方式见 [README 的模型调用章节](README.md#模型调用)。本地接口检查可用模拟 API 响应完成。

AI 入站错误使用 `{"error":{"code":"...","message":"..."}}`。常见 HTTP 状态包括参数错误 400、凭证错误 401、画像不存在 404、请求超时 408、体积超限 413 和 JSON 类型要求 415。行情与账户上游故障可通过 HTTP 200 的业务状态返回，前端同时检查 HTTP 状态和结果中的 `state` 或 `status`。
